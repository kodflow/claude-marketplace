# Blind evaluation of kodflow-gamedev, 2026-10-31

This is a rerun of the first evaluation, which was voided: the rig, three.js, animation and
anatomy agents of that run had read the corrected revision of the project under test, so the
grip and reach thresholds were calibrated on the answer. This run had no access to the project's
code at all.

**Verdict.** Two of the three criteria fail, and one run is formally invalid under the grep
guard. This report states the results as measured. No threshold or constraint was changed.

| Criterion | Result |
|---|---|
| 0 hard failures on the corrected revision (`3c7f27a`) | **fail**: 1 hard failure (`manciolino-left-foot-stays-behind`) |
| The 3 defects of `c9798c6` caught by hard constraints | **fail**: 1 of 3 caught (locomotion carry). The cut and the hand are caught only by soft constraints |
| Fingers (`b4aa00a^` against `b4aa00a`) | Not told apart by any hard constraint. Told apart by a soft one (palm distance to the grip axis) |
| `evaluated/total` | run-guard 42/44, diagonal-cut 48/58, sword-grip 72/73 |

### Hard failure on the corrected revision

`manciolino-left-foot-stays-behind` measures the vector from `foot.R` to `foot.L` against the
root's −Z axis, from contact to the end of the clip, with a maximum of 90°. Its source is
Manciolino, *Opera Nova*, "so that your left foot follows behind your right", verified exact.

It reads 159.7° on all four fixtures. In this clip the left foot stays in front of the right
through the end. The animation therefore does not perform the source's gather step.

## 6. Observations on the plugin

These are measured facts, not changes made to the plugin.

### Coverage

- **Unevaluable constraints count as coverage.** The coverage rule accepts a hard constraint that
  cannot be evaluated on the project's clips: diagonal-cut's two cut constraints need a marker the
  clip lacks. The rule checks the mapping and the source, not that the constraint can be
  measured.
- **Coverage can be pushed to sibling moves.** sword-grip marks two defects not applicable
  because another move covers them, which the rule allows. Each defect therefore rests on one
  move's hard constraints.

### Severity

The checks that tell the defective revision from the corrected one are almost all soft. Among
them are the chest-relative velocities, the forearm rotation range and the palm distance. The
panel kept the hard constraints for sign tests: handedness, side and forward/back.

### The rig-specialist-ik example

`agents/rig-specialist-ik.md` on `main` carries an example constraint whose rationale names the
project's commit: "fingers on the palm side reproduce the b4aa00a defect". It is a leak of the
evaluated project into the plugin. No run copied it: the guard found no `b4aa00a`.

### Source checking

`cache-source.py` crashed on `http.client.IncompleteRead` in all three runs. The director worked
around it by fetching bodies with curl and checking them with `--offline`.

### Run scratch directory

The run's scratch directory went to the sandbox's `$TMPDIR`, under a shared temporary root, as
`move-<slug>`. The run-guard run found two martial answers left there by an aborted earlier
blind run and moved them aside as stale. The evaluator moved each run's scratch directory away
before the next run.

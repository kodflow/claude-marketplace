# Canary report: #168 on two real profiles

Commit `ad5dae15e953881af918d9aa31f35b39462140f3`, 19 November 2026.
Claude Code 2.1.328 on both machines. Codex CLI 0.166 on the workstation and
0.170 on kepler.

## Method

The canary scripts stay outside the repository. On each machine, the steps ran
twice:

1. **Simulation** on a copy of the real profile: a copied `HOME`, with
   `CLAUDE_CONFIG_DIR` unset so that the project scope of the home directory
   aliases the user settings, as on the real machine.
2. **Real profile**, after a backup of `settings.json`, `installed_plugins.json`,
   `known_marketplaces.json` and a tar of `~/.codex/{skills,agents}`.

Claude Code, on both machines, following [the rollback runbook](install.md#claude-code):

1. Set `"ref": "<sha>"` in `extraKnownMarketplaces.kodflow.source`.
2. `claude plugin marketplace add "<declared source form>#<sha>"`: a Git URL on
   the workstation, `owner/repo` (a `github` source) on kepler.
3. Uninstall the project-scope duplicates (project path == home directory, 6
   plugins).
4. Enable the user scope again: the uninstall had disabled it.
5. `claude plugin update` for each user-scope plugin.

Codex: a clean clone at the commit, then `scripts/install.sh --codex` (native,
pinned with `--ref`).

## Findings

Folded into [install.md](install.md#rollback):

- The `add` argument must take the exact form of the declared source.
- The `ref` must be set in the declared entry before the `add`.
- Uninstalling a project-scope duplicate in the home directory disables the
  user scope.

## Remaining

- On kepler, a leftover `_shared` directory (no `SKILL.md`) of the old flat
  install stays in `~/.codex/skills`. It is harmless, and the marker rule does
  not remove it.
- `coderabbit@kodflow` was validated in a throwaway profile only: it is opt-in
  and was installed on neither machine.

## After the merge

Remove `"ref"` from the declared entry, run
`claude plugin marketplace add <declared source>` without `#<sha>`, then
`claude plugin update` for each plugin.
